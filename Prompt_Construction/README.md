# Prompt construction

Supplementary Code Listing 1 reproduces two question-type variants and the request helper from Qwen DashScope workflow A. The archived notebook defined `build_prompt` in separate cells for single-choice and multiple-choice batches. Each cell used its own instruction, read the question stem and retained lettered option fields A–G for which `pd.notna` was true. Both definitions used the same request helper. In the batch loop, `prompt = build_prompt(row)` preceded `generate_completion(client, prompt, model_name)`. The active definition depended on cell execution order.

`representative_prompt_request.py` presents the two definitions as separately labeled excerpts. For local inspection of a prompt, use one definition at a time with a synthetic pandas row containing the indicated columns. Importing the module leaves the second definition active, as Python uses the last definition with a given name. The request excerpt shows the historical SDK call, message roles and explicit parameters. It creates no client and makes no request on import or direct execution. Rate pacing and diagnostic logging are the only omitted lines within the displayed helper. The neutral cell headings and imports are supplied for publication.
